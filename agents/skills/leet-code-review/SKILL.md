# LeetCode 解答レビュー スキル

ユーザが書いた `FirstSolution/Solution.java` をコーディング面接の観点でレビューし、点数と改善ポイントを `FirstSolution/REVIEW.md` に出力する。

## 入力

- **必須**: 以下のいずれか
  - 問題ディレクトリのパス（例: `./14-longest-common-prefix/20260331/`）
  - `FirstSolution/Solution.java` への直接パス

ディレクトリが渡された場合は `FirstSolution/Solution.java` と `problem-ja.md` を自動で読み込む。

## 手順

### 1. 問題内容の把握

`problem-ja.md`（無ければ `problem.md`）を読み、問題の要件・制約・想定エッジケースを把握する。

### 2. 解答コードの読み込み

`FirstSolution/Solution.java` を読む。

**重要**: `AISolution/Solution.java` は読まない。模範解答に引きずられず公平にレビューするため。

### 3. 4観点でレビュー（各25点、合計100点）

#### 観点1: 可読性・命名・メソッド分割（25点）
- 変数名・メソッド名が意味を持つか
- ループ変数（`i`, `j`, `k`）以外で1文字変数を乱用していないか
- 責務ごとに適切にメソッド分割されているか
- マジックナンバーや重複コードがないか

#### 観点2: 時間・空間計算量（25点）
- 採用アルゴリズムの時間計算量・空間計算量を明示する
- より優れたアプローチがある場合は指摘する（例: O(n^2) → O(n) にできる など）

#### 観点3: 解法方針コメント（25点）
- **解けている場合**: コードコメントに解法方針が書かれているか。書かれていなければ減点
- **解けていない / 不完全な場合**: コメントに書かれた方針が問題に対し正しい方向性か評価

#### 観点4: エッジケース考慮（25点）
- `problem-ja.md` の制約から想定すべきエッジケースを列挙する
  - 例: 空入力、要素1個、最大サイズ、最小値・最大値、null、重複、負数、オーバーフロー
- 各ケースがコードで適切に処理されているか確認し、未対応を指摘

### 4. レビュー結果の出力

`FirstSolution/REVIEW.md` を以下のフォーマットで作成する。

```markdown
# レビュー結果: {問題番号}. {タイトル}

レビュー日: {yyyy-MM-dd}

## 総合評価: {合計}/100 点

| 観点 | 点数 |
|---|---|
| 可読性・命名・メソッド分割 | x/25 |
| 時間・空間計算量 | x/25 |
| 解法方針コメント | x/25 |
| エッジケース考慮 | x/25 |

## 観点別レビュー

### 1. 可読性・命名・メソッド分割 (x/25)
- 良い点:
  - ...
- 改善点:
  - ...

### 2. 時間・空間計算量 (x/25)
- 現在の計算量: 時間 O(...), 空間 O(...)
- 評価: ...
- 改善案: ...

### 3. 解法方針コメント (x/25)
- 状態: 解けている / 部分的 / 未解決
- 評価: ...

### 4. エッジケース考慮 (x/25)
- 想定すべきケース:
  - [x] 対応済みのケース
  - [ ] 未対応のケース
- 指摘: ...

## 改善ポイント要約
1. ...
2. ...
3. ...
```

## ルール

- すべて日本語で記述する
- 各観点の点数には必ず根拠を添える
- `AISolution/` 配下のファイルは読まない・参照しない
- 採点は辛口よりも建設的に。改善案は具体的なコード断片や手法名を示す
- 制約条件から導けるエッジケースは網羅的に列挙する
